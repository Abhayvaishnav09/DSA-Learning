# Research behind v1 (October 2026)

Short notes on what we looked at before turning the prototype into a microservices platform with a Flutter app. Each finding names the decision it drove.

## Backend architecture

| Question | Finding | Decision |
|---|---|---|
| How do services stay consistent without distributed transactions? | Current practice: database per service, local transactions, a **transactional outbox** so state and events commit together, **idempotent consumers** (processed-message table), and **sagas** (choreography or orchestration) with compensations for multi-service flows. [designgurus](https://www.designgurus.io/answers/detail/how-do-you-manage-database-transactions-in-microservices), [oneuptime 2026](https://oneuptime.com/blog/post/2026-01-24-distributed-transactions-microservices/view), [dev.to](https://dev.to/haydencordeiro/ensuring-data-consistency-across-microservices-herding-cats-with-saga-outbox-3mhe) | `packages/service-kit` ships the outbox, relay and inbox; publish, minor sign-up and account deletion are choreographed sagas. ADR-0011, ADR-0014 |
| Which message broker for a small team? | NATS is a ~20 MB Go binary using 10–50 MB of memory; JetStream adds persistence, replay and durable consumers at 1–2 M msg/s. Kafka (JVM) and RabbitMQ (Erlang) carry more operational weight; Kafka fits long-term log retention and analytics. [dev.to](https://dev.to/pvgomes/nats-is-the-messaging-backbone-i-reach-for-before-kafka-400p), [NATS docs](https://docs.nats.io/compare-nats), [Gcore](https://gcore.com/learning/nats-rabbitmq-nsq-kafka-comparison) | NATS JetStream, one stream per domain. ADR-0014 |
| NestJS or Fastify? | Fastify reaches about 2–3× Express throughput with schema validation built in; NestJS adds modules, dependency injection and enterprise patterns. Fastify is the common pick for lean microservices. [encore.dev](https://encore.dev/articles/nestjs-vs-fastify), [pkgpulse](https://www.pkgpulse.com/guides/nestjs-vs-fastify-2026) | Fastify + Zod type provider. NestJS also relies on decorator metadata, which our esbuild/vitest toolchain does not emit. ADR-0012 |
| API gateway or one backend per client (BFF)? | A gateway is generic and handles cross-cutting concerns; a BFF shapes data for one client. They can be combined, with BFFs behind a gateway. [AlgoMaster](https://algomaster.io/learn/microservices/backend-for-frontend), [Leapcell](https://leapcell.io/blog/understanding-the-core-differences-between-api-gateways-and-bffs) | One public gateway with one documented contract, because the API is handed to other developers. A few composed endpoints (`/v1/home`) cover what a BFF would add. ADR-0015 |
| Which gateway product? | Kong and APISIX (Lua), Envoy (C++, Gateway API reference) and Traefik (Go, simplest). [APISIX comparison](https://apisix.apache.org/learning-center/open-source-api-gateway-comparison/), [Luca Berton 2026](https://lucaberton.com/blog/kong-vs-envoy-vs-traefik-api-gateway-2026/) | A small TypeScript gateway (routing, JWT, rate limits, OpenAPI merge) behind a cloud load balancer or Kubernetes ingress for TLS. One language, fully tested in CI. |
| Self-hosted auth? | Keycloak gives ready-made login pages but is a heavy all-in-one server; Ory is four services plus your own UI; Better Auth is a TypeScript library, cookie-centric. [Cerbos](https://www.cerbos.dev/blog/keycloak-vs-ory), [Skycloak 2026](https://skycloak.io/blog/open-source-authentication-comparison-2026/), [noqta](https://noqta.tn/en/blog/better-auth-typescript-authentication-library-2026) | A small identity service built on standards: EdDSA JWT access tokens, JWKS, rotating refresh tokens with reuse detection, argon2id. Same API for web and Flutter. ADR-0013 |
| How should the API be documented? | Scalar (modern UI with a built-in client, OpenAPI 3.1), Redoc (clean reference) and Swagger UI (most used). [pkgpulse](https://www.pkgpulse.com/guides/scalar-vs-redoc-vs-swagger-ui-api-documentation-2026), [apiscout](https://apiscout.dev/guides/scalar-vs-swagger-ui-vs-redoc-2026) | OpenAPI 3.1 generated from Zod, merged at the gateway, Scalar UI; generated TypeScript and Dart clients prove the spec is complete. ADR-0015 |
| How do we test contracts? | Consumer-driven contracts (Pact) let consumer and provider verify independently; AsyncAPI documents events. [oneuptime](https://oneuptime.com/blog/post/2026-01-30-consumer-driven-contracts/markdown), [qaskills](https://qaskills.sh/blog/pact-consumer-driven-contract-reference-2026) | Shared Zod contracts validated on both sides, plus an OpenAPI breaking-change diff in CI. Pact becomes worthwhile when separate teams own services. |

## Mobile

| Question | Finding | Decision |
|---|---|---|
| Which framework? | Expo/React Native reuses TypeScript; Flutter (3.41+, Impeller) offers pixel-perfect UI and holds about 46% of the cross-platform market; Capacitor wraps a web app. [pkgpulse](https://www.pkgpulse.com/guides/react-native-vs-flutter-vs-expo-2026), [Pillitteri](https://pasqualepillitteri.it/en/news/8279/react-native-2026-stack-choices-vs-flutter) | Flutter (owner's choice). Grading logic is ported to Dart and checked against shared fixtures. ADR-0016 |
| How should the app be structured? | Flutter's official guide: separate the UI layer (views, view models) from the data layer (repositories, services). Repositories are the single source of truth and combine local and remote data for offline-first behaviour. [Flutter architecture guide](https://docs.flutter.dev/app-architecture/guide), [offline-first](https://docs.flutter.dev/app-architecture/design-patterns/offline-first) | MVVM with Riverpod, repositories over a generated API client and a local queue. |
| How do we build the APK without a paid service? | `flutter build apk` or `gradle assembleRelease` on a GitHub Actions Ubuntu runner, uploaded as an artifact. [testapp.io](https://blog-api.testapp.io/github-actions-mobile-app-distribution/) | `mobile-android.yml` workflow. |

## Learning content

| Finding | Use in content |
|---|---|
| Explaining variables as a **box** helps with single assignments, but after `x = 5` then `x = 7` some novices think the box holds both values; a **label** metaphor reduces that. 496 learners, WiPSCE 2018. [Hermans et al.](https://research.tudelft.nl/en/publications/thinking-out-of-the-box-comparing-metaphors-for-variables-in-prog) | Box metaphor kept, but "a box holds exactly one thing; a new value replaces the old one" is taught explicitly, with misconception `assign.multiple-values` and items on consecutive assignments. |
| Novices often think a loop **halts as soon as its condition becomes false**, before finishing the body, and understand single conditionals or loops but not combinations of them. [Sorva catalogue via ASEE](https://peer.asee.org/30811), [Eckert & Kautz taxonomy 2026](https://arxiv.org/pdf/2605.26966) | `loop.while-stops-mid-body`; nested-loop and loop-plus-if items. |
| **Parsons problems** (arranging lines) save 43–65% of practice time with the same later performance; **subgoal labels** improve results further, especially for low self-efficacy learners. [Ericson et al.](https://par.nsf.gov/servlets/purl/10099373), [Subgoals study](https://core.ac.uk/works/77773088) | `arrange-steps` stays central; optional subgoal labels group the lines. |
| Coding apps compete on short lessons, streaks, XP and goals (Sololearn) or project-building (Mimo). [Mimo](https://mimo.org/blog/mimo-vs-sololearn) | Gamification service: XP, levels and badges tied to real learning events; no shaming leaderboards. |

## Law and privacy (India)

| Finding | Decision |
|---|---|
| The DPDP Rules 2025 are notified: **verifiable parental consent** is required before processing personal data of anyone **under 18**; no tracking, behavioural monitoring or targeted ads aimed at children. [ORF](https://www.orfonline.org/expert-speak/dpdp-rules-and-the-future-of-child-data-safety), [KS&K](https://ksandk.com/data-protection-and-data-privacy/childrens-data-protection-under-indias-dpdp-rules/), [Tsaaro](https://tsaaro.com/blogs/teaching-in-the-age-of-dpdpa-when-child-safety-becomes-edtech%E2%80%99s-competitive-advantage) | Age gate at sign-up; consent service emails the parent and keeps the account `pending_consent` until approval; denial deletes it. Under-18s get no marketing and no leaderboards. ADR-0018 (supersedes the "13+" rule in doc 10). |
